## 3. Final work streams under validation

### Stream A — Order-to-document / 1C + EDO

Candidate unit:

`accepted realization/document package + evidence + exception status`

Evidence-backed questions:

- actual realizations / documents per day and month;
- minutes of operator work per unit;
- share already assisted by AI / OCR / 1C automation;
- exception rate;
- who accepts correctness;
- which actions can be prepared externally and which require the Principal;
- cost of 1C/EDO integration and access;
- whether burst capacity has value;
- when own automation becomes preferable.

### Stream B — Unregulated catalog / master-data validation

Candidate unit:

`accepted row/card or accepted batch + provenance + exception list`

Evidence-backed questions:

- cards/rows/records per day and month;
- source formats and schema variability;
- duplicate/mapping/error frequency;
- employee + AI residual work;
- sampling vs 100% acceptance;
- value of evidence/provenance;
- whether an owned AI-first catalog pipeline already exists or is planned;
- volume/stability threshold for building internally.

### Stream C — Warehouse / shipping document closure

Candidate unit:

`accepted shipment/trip document-closure package + reconciliation evidence + exceptions`

Evidence-backed questions:

- shipments/trips/document packs per day and month;
- 1C/WMS/TMS/EDO/ЭТрН systems in the loop;
- mismatch/missing-document rate;
- amount of physical-process communication per exception;
- who is allowed to sign/close/approve;
- acceptable latency and peak load;
- cost of system access/integration;
- whether an external service can prepare a closure result without taking operational authority.

## 5. Interview batch design

Initial evidence batch:

- target: **5 genuine interviews**;
- coverage: all three streams;
- no more than 2 interviews from one stream before another stream receives at least one;
- one interview may be explicitly substitute-focused (employee+AI or owned automation), because a strong negative signal is valuable evidence.

A conversation counts only when it reconstructs at least one recent real process according to `AW-020-INTERVIEW-KIT-RU.md`.

## 6. Minimum evidence record per interview

Required:

- unit of work;
- input and output;
- normal and peak volume or explicit `unknown`;
- current method;
- current AI/automation use;
- residual operator work;
- exception type/rate or `unknown`;
- acceptance owner/rule;
- time or cost anchor or `unknown`;
- data/access/security constraints;
- current buying route;
- owned-automation threshold or `unknown`;
- paid-pilot condition / reason pilot is impossible.

Do not convert unknown into zero.

## 7. C2 falsification signals

A stream should be demoted when interviews repeatedly show one or more of:

- employee + modern AI removes almost all operator burden;
- volume is too low or too stable/high, making owned automation clearly preferable;
- integration/context transfer costs as much as doing the work;
- external access is unacceptable;
- acceptance requires near-100% expert verification;
- exception rate destroys the clean unit;
- physical communication dominates the document layer;
- procurement/vendor onboarding is disproportionate to potential transaction value;
- ordinary outsourcing already provides the same result more cheaply/reliably.

## 8. Positive evidence signals

Stronger signals, in order:

`recent process → quantified volume → attributable current cost → employee+AI residual burden → explicit acceptance rule → transferable bounded stream → pilot data access → paid-pilot path → price/acceptance agreement`

An interview is not a sale.
