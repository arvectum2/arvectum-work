## 3. Final C1 top-three candidate set

### 1. Order-to-document / 1C + EDO operations

Candidate Result unit:

`accepted realization/document package + evidence + exception status`

Typical flow:

`request/document → validate → reflect in 1C/ERP → prepare standard document → EDO/status → reconcile → exception`

Why it remains first:

- broadest repeated pattern across unrelated employers;
- current exact salary anchors are abundant;
- current salary + throughput evidence exists:
  - Pioner: `15–20 realizations/day`;
  - RussKom: up to `50` returned signed document sets/day, with weaker denominator quality;
- acceptance can be expressed as required fields/statuses/reconciliation checks;
- the customer can retain accounting judgment and authority-bearing actions.

Main uncertainty:

- integration/access/security cost may erase the apparent labor advantage;
- employee + AI may already remove enough burden for smaller buyers;
- stable high-volume buyers may rationally prefer owned automation.

Existing synthetic comparison:
Scenario A in `AW-020-TOP3-SYNTHETIC-COMMERCIAL-SCENARIOS.md`.

### 2. Unregulated catalog / master-data validation

Candidate Result unit:

`accepted row/card` or `accepted batch of N normalized records + provenance + exceptions`

Typical flow:

`source feed/record → normalize → map/deduplicate → validate → proposed update → exception`

Why it remains second:

- clear measurable unit;
- structured input/output;
- current paid labor evidence across catalog, nomenclature, marketplace and master-data roles;
- relatively low consequence when final master-data authority remains with the Principal;
- naturally supports evidence/provenance.

Substitute warning is stronger than for candidate 1:

- current public gig evidence includes a numeric `10 cards/day` phrase, though compensation units are ambiguous;
- recent ПравЖизнь evidence describes an existing `Python + Flask + Excel + AI` production pipeline targeting `37,500 cards / 2 months`;
- therefore owned automation is a concrete competitor, not a theoretical future alternative.

Main uncertainty:

- no clean **current employee salary + numeric card-processing throughput** pair has been established;
- very stable/high-volume catalog flows may move quickly to owned automation;
- buyer WTP for an external accepted-result service is unknown.

Existing synthetic comparison:
Scenario C in `AW-020-TOP3-SYNTHETIC-COMMERCIAL-SCENARIOS.md`.

### 3. Warehouse / shipping document closure

Candidate Result unit:

`accepted shipment/trip document-closure package + reconciliation evidence + exception list`

Typical flow:

`shipment/trip event → collect/match docs → 1C/WMS/TMS/ЭТрН reconciliation → close recommendation/status → exception`

Why it remains third:

- clear event boundary and acceptance-friendly documents/statuses;
- repeated labor evidence;
- document mismatch and missing-doc work is observable and measurable;
- current roles show real paid budget for 1C/warehouse/EDO/ЭТрН flows.

Why it ranks below 1–2:

- stronger coupling to physical operations;
- more privileged system access;
- integration with TMS/WMS/carriers can be material;
- exception handling often requires warehouse/logistics communication.

## 4. Comparison requirement is satisfied, not validated

For all three candidates the repository contains the required four-option comparison:

1. current/manual operation;
2. employee + general-purpose AI;
3. Arvectum Work;
4. owned automation.

The numbers are **synthetic modeling assumptions**.

They are useful for interview falsification questions, not for pricing or investment decisions.

In particular:

- synthetic Work per-unit prices are not offers;
- synthetic customer savings are not validated savings;
- synthetic payback periods are not evidence of buyer thresholds;
- vacancy salaries are role-level labor-budget anchors, not fully loaded process cost.

## 5. What C1 actually proves

Public evidence now supports these factual statements:

1. Russian employers repeatedly pay for the underlying document/data functions.
2. Those functions recur across titles and employers.
3. A bounded repetitive machine-work slice can be specified for every counted record.
4. The same jobs also contain human/Principal residual work that must not be silently automated.
5. Three work streams are concrete enough to target in focused buyer validation.
6. Both `employee + AI` and `owned automation` are credible substitutes and must remain in the comparison.

## 6. What C1 does NOT prove

C1 does **not** prove:

- demand for Arvectum Work;
- willingness to transfer the process externally;
- willingness to pay;
- real customer volume/peaks;
- real exception rate;
- acceptance owner/rules;
- data/security acceptability;
- Work accuracy or acceptance rate;
- positive contribution margin;
- repeat purchase;
- Business PASS for AW-020;
- permission to build a marketplace.

Therefore:

`AW-020-C1 complete ≠ AW-020 GO`

and

`Technical/public-evidence PASS ≠ Business PASS`.
