# PRODUCT-DECISION-001 — Arvectum Work продаёт поток выполненной цифровой работы

Status: `Accepted / Discovery`
Date: `2026-09-17`
Owner: `Arvectum Work`
Authority: `Principal product decision within current Discovery scope`

## Решение

Arvectum Work проверяет не идею «ещё одного интерфейса к AI» и не продажу отдельных AI-агентов.

**Коммерческая гипотеза продукта:**

> Arvectum Work принимает на себя поток повторяемой цифровой работы компании и возвращает принятые результаты с измеримыми сроком, качеством и стоимостью. Заказчик платит за выполненную и принятую работу, а не за модель, промпты, лицензии или внутреннюю эксплуатацию AI.

Короткая формулировка для рынка:

> **Не покупайте AI и не управляйте AI. Покупайте выполненную цифровую работу.**

Внутренний тезис сохраняется:

> **We don't sell agents. We make machine work tradable.**

## Что является единицей продажи

Не отдельный prompt и не доступ к модели.

Базовая коммерческая единица:

`рабочий поток → единицы/пакеты работы → измеримый Result → Acceptance → цена за принятую единицу/пакет`

Примеры:

- обработка входящего потока документов;
- нормализация товарных/коммерческих данных;
- регулярная сверка и обогащение данных;
- мониторинг изменений;
- повторяемая обработка закупочных/коммерческих документов;
- другие цифровые операции, где вход, результат и качество можно измерить.

## С чем продукт реально конкурирует

Главные substitutes:

1. сотрудники без AI;
2. сотрудники с ChatGPT/другими универсальными моделями;
3. обычный аутсорсинг, который внутри может использовать AI;
4. SaaS/RPA/специализированные инструменты;
5. собственная автоматизация или собственный AI-агент клиента.

Arvectum Work не должен предполагать преимущество над ними. Преимущество должно подтверждаться реальной экономикой конкретного процесса.

## Обязательный тест «сотрудник + ChatGPT»

Если компетентный сотрудник с доступной современной универсальной моделью может обработать единицу работы за несколько минут без существенного контроля, повторных итераций и операционного сопровождения, такая работа **не является приоритетным wedge** для Arvectum Work.

Искомая зона продукта — процессы, где даже после появления AI остаётся заметная операционная нагрузка:

- большой или переменный объём;
- постоянный запуск и контроль множества однотипных операций;
- ручная проверка и разбор исключений;
- перенос результатов между системами;
- необходимость поддерживать пропускную способность, сроки и качество;
- потребность в людях, которые управляют AI-процессом.

Ценность Work должна быть не «лучше написать промпт», а **снять с заказчика операционное выполнение потока**.

## Обязательный тест «покупать работу или владеть автоматизацией»

Для каждого перспективного процесса Work должен сравнивать:

- стоимость покупки выполненной работы через Work;
- полную стоимость ручного процесса;
- полную стоимость собственного AI/автоматизации клиента.

Если процесс стал достаточно большим, стабильным и предсказуемым, чтобы собственная автоматизация была устойчиво дешевле Work, это **не провал**.

Work должен уметь показать клиенту экономическую точку перехода.

Возможный следующий продукт/решение для такого клиента определяется Arvectum Company отдельно; потенциально это система с собственными AI-исполнителями на базе Arvectum OS. Arvectum Work не владеет Arvectum OS и не переносит свои marketplace/service semantics в OS.

## Когда Work особенно уместен

Гипотеза сильнее, если одновременно присутствуют несколько условий:

- ручная цифровая работа уже стоит заметных денег;
- объём повторяется или приходит потоком;
- объём плавает и не оправдывает постоянный штат/инфраструктуру;
- отдельный проект автоматизации слишком дорог или долог;
- компания не хочет содержать собственную AI-компетенцию;
- работу можно принимать по измеримому результату;
- исключения можно выделять отдельно, а не скрывать внутри «среднего качества»;
- цена за принятую единицу ниже альтернатив с учётом полного операционного контура.

## Когда Work, вероятно, не нужен

- редкая маленькая задача, которую сотрудник решает в ChatGPT за несколько минут;
- уникальная экспертная работа без повторяемого процесса;
- процесс с настолько большим и стабильным объёмом, что собственная автоматизация явно окупается;
- процесс, где стоимость проверки сопоставима со стоимостью ручного выполнения;
- процесс с недопустимым риском ошибки и без надёжной Acceptance;
- работа, где заказчик всё равно вынужден фактически управлять каждой AI-итерацией.

## Следствие для интерфейса

Основной интерфейс Work не должен выглядеть как очередной чат с моделью.

Для зрелого рабочего потока заказчик должен видеть прежде всего:

- объём входящей работы;
- сколько обработано;
- сколько принято;
- сколько ушло в исключения;
- время выполнения;
- качество;
- стоимость;
- причины возвратов;
- историю работы исполнителей.

Прототип для Discovery должен демонстрировать именно управление потоком цифрового труда, а не «умный prompt box».

## Следствие для Discovery

Основной объект интервью теперь — **реальный рабочий процесс**, а не отдельная AI-задача.

Нужно измерять:

- единицу работы;
- месячный/недельный объём;
- вариативность и пики;
- текущий штат/часы;
- фактическую стоимость;
- использование ChatGPT/другого AI сегодня;
- сколько операторской работы остаётся после AI;
- долю исключений;
- требования к качеству и срокам;
- владельца приёмки;
- цену внешнего результата;
- условия, при которых выгоднее собственная автоматизация.

## Что не доказано этим решением

Решение фиксирует **направление проверки**, а не подтверждение рынка.

Не доказано, что:

- российские компании захотят отдавать такие потоки наружу;
- Work сможет быть дешевле сотрудника + ChatGPT;
- Work будет дешевле традиционного аутсорсинга;
- исполнение будет иметь положительную unit economics;
- заказчики согласятся платить за принятую единицу/пакет;
- появится ценность именно marketplace-механизма, а не managed service;
- переход к собственной системе на базе Arvectum OS станет коммерчески значимым каналом.

Все эти пункты должны подтверждаться реальными транзакциями и эксплуатационными данными.
